Documentation

Installation, use, access control and recovery guidance for authorized administrators.

Uninstall deletes saved analyses.

Uninstalling removes Profitability Analysis snapshots. Reinstalling starts empty. Recovery requires a verified backup and preserved encryption configuration. A full restore may roll back unrelated site data. Recovery is not guaranteed.

Published app version: 0.2.0. GitHub release v0.2.0 · Source repository. Verified release commit: e72452bd9a3db777fc778867b85d4724c19dff9c.

Exact-commit CI passed static checks and 145 integration tests on each target: Frappe/ERPNext 16.52.0, and Frappe 16.56.0 / ERPNext 16.54.0. Both targets had zero failures and skipped tests. Full lifecycle and performance acceptance was scoped to 16.52.0. Automated CI does not establish production capacity or complete browser compatibility.

Compatibility and prerequisites

Verified: Frappe/ERPNext 16.52.0, Python >=3.14,<3.15. Tested assets use Node.js 24.x and Yarn 1.22.x; MariaDB and Redis are required. ERPNext must already be installed. Broader compatibility is not implied; see the exact-commit CI scope above.

Installation

These are operator examples, not commands executed by this page. Replace all placeholders, verify the Bench/site identity and back up first. Run get-app only if the checkout is absent. The source URL matches the public GitHub repository. Use the published release and verify its exact revision.

cd /absolute/path/to/target/frappe-bench
bench --site <site-name> list-apps
bench --site <site-name> backup --with-files
bench get-app --branch version-16 https://github.com/bhushanraut4343-collab/order_profitability_predictor.git
# Verify the approved revision before installation:
git -C apps/order_profitability_predictor rev-parse HEAD
bench --site <site-name> install-app order_profitability_predictor
bench --site <site-name> migrate
bench build --app order_profitability_predictor
bench --site <site-name> clear-cache
bench --site <site-name> list-apps

Historical full acceptance covered revision 3a24c06, source version 0.2.0-rc.1. Release 0.2.0 at e72452bd9a3db777fc778867b85d4724c19dff9c subsequently passed exact-commit CI. The version-16 branch can move; do not treat an unreviewed tip as the tested release. For Marketplace-managed sites, use the verified platform workflow rather than assuming shell access.

Upgrade safely

Take and verify a full backup, review a clean source checkout and the approved revision, then run normal migration, app asset build and site cache clear. Restart through the deployment’s normal service manager when required. A source checkout alone is not an upgrade or rollback.

Migration can run pending patches from other installed apps. Review them first; never use force or skip-failing options to hide errors. A shared Bench checkout can affect multiple sites. Validate calculations, original snapshots and restricted-user access afterward.

Use the app

  1. Open a saved draft or submitted Quotation and select Check Profitability.
  2. Read completeness and risk warnings before using the estimate.
  3. Select Save Analysis to calculate and store a fresh snapshot.
  4. Select View History, choose an analysis and Compare with Current Estimate.

History displays 20 analyses per page. Viewing or comparing does not create a snapshot. Saving can differ from a preview if saved source data has changed.

Permissions

Users require Quotation, relevant BOM, Company and financial-field access. Sales Manager and System Manager have snapshot create/read grants, but those roles alone do not grant every source permission. Sales Manager plus Manufacturing User was validated for ordinary app access. Purchase observations additionally require purchase-document and field access.

Source-access revocation also restricts historical financial data. Snapshot sharing is blocked. Do not remove masking or grant broad roles merely to make a result appear. Normal application checks do not restrict trusted database/server administrators.

Configuration

The minimum-margin threshold defaults to 15%; an authorized administrator may configure 0–100:

bench --site <site-name> set-config order_profitability_minimum_margin 15 --parse
bench --site <site-name> clear-cache

Rate review uses a fixed 90-day rule. Purchase-date evidence does not prove when a saved BOM rate was refreshed. Valuation evidence review is bounded to 500 matching rows per transaction type/company and 30 purchase-document checks per calculation. Price List and Last Purchase Rate use their own dated-evidence rules. New snapshots omit live valuation purchase observations; older snapshots are not rewritten.

Estimation scope and limitations

Calculations use saved records, exclude taxes and ignore unsaved Quotation edits. Saved BOM rates may be outdated. Purchase evidence does not automatically refresh them. Results are gross manufacturing estimates, not guaranteed profit or full actual-cost accounting; completeness does not establish that every real overhead was recorded.

  • Unsupported: scrap-recovery and secondary/by-product/co-product allocation.
  • Unsupported: valuation-priced manufactured subassemblies, operation-level semi-finished routing and variant-template BOM substitution.
  • Missing, zero or inconsistent costs, invalid quantities and circular BOMs can leave totals unavailable. Intentional free inputs can also be treated as incomplete.
  • Purchase observations require access to submitted, non-return records, the same company/base currency and exact material UOM. No currency or UOM conversion is inferred. Missing, conflicting or bounded-out observations are withheld.

Full backups and recovery

bench --site <site-name> backup --with-files

Preserve database, public/private files, site configuration, credential-encryption material and any separate backup-encryption material. Record checksums and verify recovery in an independent destination. Checksums alone do not prove recoverability.

Before restoration or operations that could access encrypted values, establish destination isolation and securely restore required encryption configuration. Preserve independent database credentials, sockets and Redis settings; do not copy the source configuration wholesale. Keep web/background processing and outbound integrations disabled during test recovery.

Restoring the database may overwrite site settings. Recheck email suppression, scheduler state and integrations after restoration, before migration or normal operation. Validate original snapshot IDs, JSON, dates, links, attachments, permissions and encrypted values.

Full recovery can roll back unrelated data.

Restoration may return ERPNext and other customer records to the backup’s point in time. Never restore over an existing site without explicit authorization and a reviewed data-loss plan.

Troubleshooting

For missing buttons, confirm installation, a saved Quotation, approved asset build and cache clear, then reload Desk. For denials, check source/company/field access. For incomplete costs, inspect saved BOM inputs and warnings. Missing purchase evidence can be intentional withholding due to permissions, comparability, conflicts or limits. Do not uninstall as a workaround.
